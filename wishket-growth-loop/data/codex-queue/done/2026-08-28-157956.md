# 운영 중인 웹사이트 4개 상시 유지보수 지원 제안

소비자 신청 정보를 본사 또는 전국 센터로 연결하는 웹사이트 4개와 관리 화면을 기존 업체로부터 인계받아, 신규 구축 없이 월 단위로 안정적으로 운영하는 과업으로 이해했습니다. 사내 개발자가 없는 상황이므로 단순 요청 처리뿐 아니라 현재 구조를 빠르게 파악하고, 장애·데이터 누락·변경 영향도를 이해하기 쉬운 언어로 설명하며 운영 기록을 남기는 것이 중요합니다.

## 수행 전략

1. 인수 초기에 4개 사이트의 기술 스택, 호스팅·배포 구조, 도메인, 저장소, DB, 외부 연동, 관리자 권한, 백업 현황을 목록화합니다. 기존 업체의 미해결 이슈와 정기 작업도 인수 체크리스트로 확인합니다.
2. 소비자 입력부터 센터 배정·본사 접수·관리자 확인까지 데이터 흐름을 추적해 핵심 경로와 장애 위험 구간을 정리합니다. 사이트별 공통 기능과 개별 기능을 구분해 변경 시 다른 사이트에 미치는 영향을 먼저 검토합니다.
3. 요청은 긴급 장애, 오류 수정, 콘텐츠·설정 변경, 개선 제안으로 분류하고 접수·진단·완료·검수 상태를 기록합니다. 월 예산 안에서 처리 가능한 범위를 투명하게 관리하며 큰 기능 변경은 사전 산정 후 별도 합의하겠습니다.
4. 운영 중인 데이터를 다루므로 변경 전 백업, 테스트 환경 또는 재현 절차, 최소 단위 배포, 롤백 기준을 적용합니다.

## 전문성과 관련 경험

홈페이지, 신청·문의 폼, 관리자 화면, 반응형 UI를 함께 운영해 온 경험을 바탕으로 사용자 화면과 내부 처리 화면을 한 흐름으로 점검할 수 있습니다. `마르다누수탐지`의 상담 전환형 현장 서비스 구조는 지역 기반 문의가 정확히 접수되는 흐름을 점검하는 데, `클린파트너`의 B2B 견적 문의 구조는 고객 입력을 담당자 업무로 연결하는 운영 관점에 연결할 수 있습니다. AI는 로그 분류, 영향 범위 초안, 회귀 테스트 항목 점검을 보조하는 수준으로만 활용하고 수정과 배포 판단은 직접 검수합니다.

## 첫 달 일정

- 1주차: 자료·계정 인수, 실행 환경 확인, 4개 사이트 자산 및 위험 목록 작성
- 2주차: 핵심 신청 경로와 관리자 처리 흐름 점검, 백업·복구 확인
- 3주차: 우선 오류 처리, 모니터링·작업 기록 방식 정착
- 4주차: 회귀 점검, 월간 처리 내역과 다음 달 우선순위 보고

이후에는 월 단위로 요청 처리와 예방 점검을 반복하며, 공고의 월 30만 원 범위에서 기본 대응 시간과 포함 업무를 먼저 합의하겠습니다.

## QA 및 운영

4개 사이트별로 신청 폼 필수값, 개인정보 동의, 중복 전송, 센터 배정, 알림·접수 결과, 관리자 검색·수정 권한, 모바일 화면, 주요 브라우저를 점검합니다. 변경 시 관련 경로를 회귀 테스트하고 작업 전후 상태, 변경 파일, 배포 시각, 롤백 방법을 기록하겠습니다. 장애는 영향도와 재현 조건을 먼저 공유하고, 데이터 손실 위험이 있으면 임시 조치와 근본 수정안을 구분해 대응합니다.

## 확인 질문

1. 4개 사이트의 기술 스택과 호스팅, 저장소, DB 접근 자료를 기존 업체에서 인계받을 수 있나요?
2. 월 30만 원에 기대하는 기본 작업 시간, 응답 시간, 긴급 대응 시간대는 어떻게 되나요?
3. 소비자 신청 정보가 센터로 배정되는 규칙과 실패 시 수동 처리 절차가 있나요?
4. 현재 알려진 오류, 반복 요청, 보안 또는 백업 우려 사항이 있나요?
5. 운영·배포 승인 담당자와 검수 방식은 어떻게 정해져 있나요?

초기 인수 과정에서 실제 구조와 월간 요청량을 확인한 뒤, 예산 안에서 안정적으로 지속 가능한 유지보수 범위를 명확히 정리하겠습니다.

## 자체 QA

- 금지 표현 미사용
- 외부 이메일·전화번호·홈페이지 주소 미포함
- 공개 프로젝트 정보와 제공된 포트폴리오 자료만 사용
- 서버에서 실제 지원 제출하지 않음
