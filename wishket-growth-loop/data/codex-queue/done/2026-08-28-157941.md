# 아임웹 연동 패키지 여행사 전용 ERP 신규 구축 지원 제안

현재 사용 중인 여행 ERP를 대체하면서 아임웹 홈페이지를 고객 접점으로 유지하고, 행사·예약·정산·통계 업무를 하나의 운영 흐름으로 연결하려는 프로젝트로 이해했습니다. 단순 홈페이지 제작보다 ERP의 업무 규칙과 아임웹에서 유입되는 고객·예약 데이터의 연계 기준을 먼저 확정하는 것이 핵심입니다. 공개 범위에서 상세 연동 방식은 확인되지 않으므로, 착수 시 아임웹 API·웹훅 사용 가능 범위와 기존 데이터 이관 조건을 우선 검증하겠습니다.

## 수행 전략

1. 담당자 인터뷰와 기존 화면·자료 분석을 통해 상품, 출발일, 행사, 예약자, 결제·환불, 정산, 거래처, 통계의 업무 흐름을 정리합니다. 역할별 권한과 상태 변경 규칙도 함께 정의해 누락과 중복 입력을 줄입니다.
2. 아임웹과 ERP 사이의 데이터 소유권, 동기화 방향, 실패 시 재처리 기준을 설계합니다. 직접 연동이 제한되는 항목은 관리자 확인 절차나 안전한 반입 방식으로 분리하고, 확인되지 않은 기능을 전제로 개발하지 않겠습니다.
3. ERP는 실무자가 자주 쓰는 행사 현황, 예약 검색, 정산 마감, 변경 이력, 통계 조회를 중심으로 IA와 화면을 설계합니다. 목록 필터, 엑셀 입출력, 권한, 감사 로그처럼 운영에 필요한 기능을 우선순위화합니다.
4. 홈페이지 영역은 상품 탐색부터 문의·예약 전환까지 모바일 흐름을 점검하고, ERP와 연결되는 입력 항목의 검증 및 개인정보 처리 범위를 명확히 합니다.

## 전문성과 관련 경험

기획, IA, UI/UX, 반응형 프론트엔드, 관리자 기능, 배포와 운영 인계까지 한 흐름으로 진행합니다. `쓰리웨이펜션`의 예약 전환형 숙박 홈페이지 경험은 상품·요금·예약 흐름을 고객 관점에서 구조화하는 데 연결할 수 있고, `온다 애드`의 대시보드 UI 경험은 여러 상태와 지표를 빠르게 파악하는 운영 화면 설계에 연결할 수 있습니다. AI는 요구사항 분류, 화면 항목 초안, 테스트 케이스 점검을 보조하는 수준으로 활용하며 최종 업무 규칙과 결과물은 담당자가 직접 검수합니다.

## 일정 제안

- 1~2주차: 현행 업무 분석, 연동 가능성 검증, 요구사항·권한·데이터 모델 확정
- 3~4주차: IA, 핵심 화면 설계, UI 시안, 기술 검증
- 5~8주차: ERP 핵심 기능과 아임웹 연계 개발, 단위 테스트
- 9~10주차: 데이터 이관 리허설, 통합·권한·예외 테스트, 사용자 검수
- 11주차: 수정, 배포, 운영 문서와 관리자 교육

공고의 75일을 기준으로 하되, 기존 데이터 품질과 아임웹 연동 범위가 확정된 뒤 세부 마일스톤을 고정하겠습니다.

## QA 및 운영

예약 상태 전이, 중복 접수, 금액 계산과 정산 합계, 취소·환불, 권한별 접근, 동시 수정, 연동 실패와 재시도, 엑셀 입출력, 모바일 입력을 시나리오별로 검증합니다. 배포 전 백업·복구와 이관 리허설을 수행하고, 배포 후에는 오류 로그와 핵심 지표를 확인할 수 있도록 운영 절차를 문서화하겠습니다. 신규 기능은 우선순위와 영향 범위를 합의한 뒤 별도 변경 관리로 진행하겠습니다.

## 확인 질문

1. 아임웹에서 ERP로 전달해야 하는 주문·예약·회원 항목과 사용 중인 요금제 또는 연동 수단은 무엇인가요?
2. 기존 ERP의 데이터 규모, 내보내기 형식, 반드시 보존해야 하는 이력은 어디까지인가요?
3. 행사 원가·판매가·수수료·거래처 정산의 계산 규칙과 마감 취소 규칙이 문서화되어 있나요?
4. 사용자 역할과 승인 단계, 개인정보 접근 및 보관 정책은 어떻게 구성되어 있나요?
5. 75일 안에 반드시 오픈해야 할 1차 범위와 이후 고도화 가능 범위를 구분할 수 있을까요?

예상 금액 2,000만 원과 75일을 기준으로 제안하며, 비공개 상세 요구와 연동 기술 검증 후 범위·일정을 함께 확정하겠습니다.

## 자체 QA

- 금지 표현 미사용
- 외부 이메일·전화번호·홈페이지 주소 미포함
- 공개 프로젝트 정보와 제공된 포트폴리오 자료만 사용
- 서버에서 실제 지원 제출하지 않음
